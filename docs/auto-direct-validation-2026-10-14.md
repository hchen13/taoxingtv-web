# 2026-10-14：macOS 自动物理出口识别验证

本轮将直连从手动指定网卡改为 macOS 默认自动识别。服务继续在原 Mac 的 `:8090` 运行，不改变局域网访问方式。

## 实现范围

- 不存在本地配置或环境变量时，macOS 默认 `auto`。其他平台默认 `off`。
- 读取硬件端口、IPv4 地址、链路状态、按网卡查询的默认路由，以及系统主出口和网络服务顺序。TUN、回环、虚拟网桥、掉线网卡、自分配地址和没有默认出口的接口不会入选。
- 支持 `auto`、手动网卡名、`off`，以及旧版空字符串关闭行为。手动配置不会被静默覆盖。
- 找不到有效出口或无法确定多个出口的优先级时明确报错，不退回未绑定的连接。
- `node direct-network.js` 只读显示识别结果；每次新启动模拟器重新识别，运行中不热切换网卡。
- 网卡绑定继续只注入本项目启动的 QEMU。原生 socket 模块本轮没有改变。

新增场景包括另一台 Mac 使用 Wi-Fi `en0`、USB 网卡 `en12`、多网卡优先级、TUN 占据默认路由及主服务、掉线但残留地址、关闭的服务、只有局域网地址、错误或被拒绝的 scoped route、无网卡、只有 IPv6、明确指定无效网卡，以及下一次启动重新识别出口。

这些不同网络拓扑使用模拟的系统查询结果测试，未修改本机真实网卡、TUN 或路由来构造环境。既有原生测试仍实际编译并加载动态库，检查 TCP 回环、UDP `connect` / `sendto` / `sendmsg`、非 QEMU 进程保持原行为，以及网卡不存在时连接失败。

## 本机真实运行

1. 将原先写死 `en1` 的本地配置移入忽略的诊断备份，确认无配置、无 `TXTV_DIRECT_INTERFACE` 覆盖时，诊断结果为 `mode: auto`，自动选择本机当前物理出口 `en1`，依据为 `default-route`。
2. 仅冷启动本项目模拟器和 Node 服务。启动日志显示“自动识别物理出口”，模拟器内的应用正常完成授权。
3. 真实播放黄石第三季 E4。引擎就绪后首包总耗时约 2.33 秒；恢复到 5:36 位置的另一次取流首包约 1.65 秒。随后浏览器播放到 7:03，`readyState=4`，无媒体错误，当前位置后有约 112 秒连续缓冲。
4. 通过只读 socket 选项查询确认 QEMU 已加载绑定模块，E4 的 `64.62.198.75:3029` 和 `64.62.198.76:3029` 连接绑定到自动选出网卡的接口索引。约 6 秒采样中，两节点共收到约 27 MB 数据。此数值是 socket 收流量，不是有效视频吞吐或下载文件增长，不能据此宣称持续播放速度达到某个值。
5. 同期查询 Clash 连接接口，没有 QEMU 连接。结合实际 socket 绑定及收流证据判断直连，没有单凭 Clash 面板缺少记录下结论。

变更前后读取的系统 DNS、系统代理、默认路由一致；Clash 配置 SHA-256 与核心 PID 也一致。本轮没有修改 Clash、DNS、系统代理、TUN 或系统路由，没有重启代理核心。

本机证据保存在被忽略的 `cache/diagnostics/auto-direct-20261014/` 和 `cache/diagnostics/live-20261014/direct-runtime-auto-*.json`，不提交包含环境信息的诊断目录。
