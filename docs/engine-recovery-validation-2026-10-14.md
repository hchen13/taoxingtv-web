# 2026-10-14：引擎断连与缓存续播验证

本次修复恢复过程中会阻塞服务、丢弃可播放缓存的问题。本机实播黄石第三季 E3、E4，并分别中断整个模拟器和 Android 原生 App。测试窗口内没有观察到播放中的缓冲等待，接续前后保持同一个 HTTP 播放会话。

## 41 秒的来源与已确认的边界

此前 18:34:12 的 macOS 崩溃报告记录的是整个 `qemu-system-aarch64-headless` 进程 `SIGABRT`，故障栈为 `hvf_vcpu_exec + 372`，不是仅仅 Android App 退出。核对本机 Emulator 37.1.11 二进制反汇编，该位置对应 Hypervisor 返回未处理退出原因后的 `abort()` 分支。随后项目重新启动 Android、Frida、App 并完成授权，18:34:53 才重新出流，总计约 41 秒。

旧启动方式丢弃了模拟器 stderr，因此没有保留当时具体的虚拟化退出值，无法进一步证明底层触发条件。没有证据把该崩溃归因于 Clash 或网卡绑定模块，也没有通过修改代理、DNS 或路由来处理它。核对过 [Android Emulator 官方发行说明](https://developer.android.com/studio/releases/emulator)，不能据此认定某个更新已修复本次崩溃栈。

**本次没有宣称消除了 macOS / Emulator 底层崩溃，也没有把完整冷启动缩短为几秒。** 修复目标是让恢复尽早在后台进行，期间继续用已缓存的视频观看。缓存耗尽、长期断网、不能解码的媒体或源长期无数据仍可能导致等待。

## 代码修复

- 所有 ADB 调用改为异步，包括最长 120 秒的 `wait-for-device`、启动检查和图片读取；等待 Android 不再阻塞 HTTP、缓冲反馈或磁盘视频投递。必须成功的等待/端口转发会明确报错，Android 启动超时也不会继续假定已就绪。
- 端口转发操作按调用顺序执行，避免旧端口的异步删除晚到，删掉复用该端口的新转发。
- 活动点播会话丢失原生引擎后立即后台启动替代引擎。磁盘缓存满时，不再等 ffmpeg 的 stdout 排空、缓存开始消耗后才启动；实际续接仍由原会话 token 控制。
- 旧 Frida 会话迟到的 detach 通知不会清掉已连接的新会话。主动关闭不会触发重新启动。
- 浏览器遇到网络错误时，先保留仍可播放的 MSE 缓冲和用户暂停状态；临近用尽再重试，且不依赖可能已经离线的状态接口。尚未完成的跳转、解码错误仍立即进入相应恢复流程。
- 新增启动阶段耗时、模拟器进程退出和原始 stdout/stderr 日志。原始日志仅保存在忽略目录 `cache/emulator.log`，上一次保存在 `cache/emulator.log.previous`。媒体错误以结构化文本保留实际位置和错误信息。
