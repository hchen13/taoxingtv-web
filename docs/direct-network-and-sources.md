# 本机直连与视频源清单

TXTV 可以继续在同一台 Mac 上做服务器，家里的设备继续访问 `http://服务器名.local:8090/`。视频源的外网请求主要由 Android 模拟器的 QEMU 进程发出；浏览器连接的是 Node 服务，本地 ffmpeg 读取模拟器转出的流。

**动态 P2P 节点没有一张永久完整的 IP 白名单。** 直播按频道 ID 请求节点，点播目录中的 IP 也不一定覆盖随后加入的 peer。同一个频道在短时间内就可能换节点。下面的地址清单用于识别连接和排查，不能保证未来所有节目直连。

## macOS：自动识别物理出口

项目支持把自己启动的模拟器出站 socket 绑定到物理网卡，使用 macOS 的 `IP_BOUND_IF` / `IPV6_BOUND_IF`。它不修改 Clash、TUN、系统代理、DNS 或路由表，不重启代理核心，也不需要换服务器。节点 IP 变化时，新的连接仍使用所选网卡。

**macOS 默认启用自动识别，不需要本地配置文件。** 每次由项目启动新模拟器时重新识别，不把上一台 Mac 的网卡名存成默认值。需要 Xcode Command Line Tools，以及允许加载本地动态库的 Android SDK 模拟器。已在 Apple Silicon 的本机模拟器上验证；其他版本应检查实际加载和收流结果，不能仅看启动日志就认定成功。不要为此关闭 SIP 或放宽系统安全设置。其他平台默认不启用此功能，显式请求启用时会报告不支持。

识别依据：

1. 从 macOS 硬件端口列表中获取物理 `en*` 接口，排除 TUN、回环和虚拟网桥。
2. 核对有效 IPv4 地址、链路已连接，以及该网卡自己的 IPv4 默认路由；不会把只有局域网地址、掉线或自分配 `169.254.*` 地址的接口当作出口。
3. 优先选择系统当前的物理默认出口，再参考主网络服务；若它们被 TUN 占用，则按 macOS 网络服务顺序，在可用的物理出口中选择。无法确定多个出口的优先级时明确报错，不按 `en0` / `en1` 的编号猜测。

这里只使用 `networksetup -list…`、`ifconfig <网卡>`、`scutil show` 和 `route -n get` 等读取操作。[Apple 的 route 手册](https://github.com/apple-oss-distributions/network_cmds/blob/main/route.tproj/route.8)说明 `get` 用于查询路由，`-ifscope` 用于指定查询的网卡范围；不会调用路由增删或系统网络设置命令。主网络服务取自 [macOS 动态网络状态](https://developer.apple.com/documentation/systemconfiguration/scdynamicstore-gb2)。

在部署机器上检查自动识别结果：

```sh
node direct-network.js
```

该命令只显示模式、网卡、地址、网关和选择依据，不启动模拟器，不发起外部探测，也不编译模块。它证明的是出口选择；实际直连仍需核对模拟器加载的模块和视频连接。

### 可选配置与升级

配置优先级：环境变量 `TXTV_DIRECT_INTERFACE` → 项目根目录 `direct-network.json` 的 `interface` → macOS 默认 `auto`。可用值：

| 值 | 行为 |
| --- | --- |
| `auto` | 每次启动模拟器自动识别物理出口 |
| `en0` 等本机物理网卡名 | 手动指定，仍检查该网卡的链路和默认路由；无效时报错 |
| `off` 或空字符串 | 明确关闭绑定，恢复系统原有出网行为，可能经过代理 |

已有手动配置会被保留。旧版用户若想由固定网卡切换到自动识别，可删除本地文件，或将内容改为：

```json
{"interface":"auto"}
```

也可以设置环境变量 `TXTV_DIRECT_INTERFACE=auto`。配置文件已加入 `.gitignore`，不会把一台机器的网卡名带给其他部署者。

设置后，**重启本项目的模拟器和 Node 服务**。只重启 Node、复用旧模拟器不会加载新模式。关闭模拟器前，应确认它属于本项目，并保存正在看的进度；局域网内正在看的客户端会短暂断流。网页地址、端口、账号数据不变。

模块由 `native/direct-network.c` 编译到 `cache/direct-network/`，仅通过模拟器子进程的 `DYLD_INSERT_LIBRARIES` 加载。它只对 `qemu-system-*` 生效，TCP/UDP 外连使用所选网卡，回环上的 ADB/Frida 保持原路。Node、浏览器、Codex、Clash 及其他进程不会得到这个环境变量。网卡不可用时连接报错，不悄悄退回代理路径。

回退：设置环境变量 `TXTV_DIRECT_INTERFACE=off`，或将文件改成 `{"interface":"off"}` 并清除优先级更高的环境变量；再重启本项目的模拟器和 Node 服务。**删除配置文件现在表示恢复自动识别，不再表示关闭。** 无需恢复任何代理配置。

限制：这作用于本项目模拟器的全部出站连接，包括 Android 后台请求。运行中的模拟器不会热切换网卡；从 Wi-Fi 换到有线等情况，需重启本项目模拟器，自动模式会重新识别，无需改网卡名。找不到可用物理出口时会明确报错，连接不悄悄退回代理。当前取流需要 IPv4 出口，只有 IPv6 的环境会报告不支持；有地址和默认路由也不保证上游或需要网页认证的网络可用。它不改系统 DNS，若其他网络工具提供了无法直连的假 IP，仍需单独核对解析结果。此模式针对已验证的 macOS socket 路径，不能承诺绕过所有第三方 VPN/网络过滤器，也不保证源本身的带宽。

## 代理自身支持按进程分流时

也可以在服务器的代理里，把实际取流进程放到 DIRECT。这样不依赖节目地址，也不用在每台观看设备上添加上游 IP 表。该办法需要用户选择并修改自己的代理规则；项目不会自动改代理配置。

Mihomo/Clash 的例子（替换成连接面板显示的真实可执行文件路径）：

```yaml
prepend:
  - PROCESS-PATH,/absolute/android-sdk/emulator/qemu/darwin-aarch64/qemu-system-aarch64-headless,DIRECT
```

在 Clash Verge 当前订阅的规则扩展中添加这条 prepend，保留已有规则。规则模式按顺序匹配；不要只编辑会被重新生成的运行配置。确认连接面板命中了这条进程规则，而非默认代理策略。参见 [Mihomo 路由规则](https://wiki.metacubex.one/config/rules/) 和 [Clash Verge 规则扩展](https://www.clashverge.dev/guide/rules.html)。

路径规则会匹配使用同一 QEMU 可执行文件的其他模拟器；如果还运行开发用 AVD，需要考虑这个范围。不要把所有 `node`、浏览器或整个 SDK 目录一概直连。若取流实现变更后出现其他实际联网进程，应根据连接证据补充，不能只猜进程名。主机上的代理看到的是 QEMU，不是 Android 内的 `com.wys.iptvgo` 包名。

仅设置 `NO_PROXY`、清空 `HTTP_PROXY` 或给浏览器放行 `.local`，不能替代这里的出站控制：本次确认原生搜索和视频取流包含 UDP，且主机 TUN 会影响这些连接。[Mihomo TUN 说明](https://wiki.metacubex.one/config/inbound/tun/)描述了自动路由接管的范围。

## 如何判断实际效果

同时核对三件事：实际视频连接使用的出口、收到的有效视频数据、浏览器当前位置之后的连续可播缓冲。连接未出现在 Clash 面板里，单独不足以证明可用直连；配置了 DIRECT，也不等于有足够带宽。

本次另发现 Golf HD 的原生回调对象与 APK 注册的直播类不匹配，崩溃后浏览器把剩余缓冲当作有限视频，续播重复旧片段。已改用对应直播回调类并在直播 EOF 后重取新流。这与代理分流是两个问题，不能用一条直连规则替代播放恢复修复。
