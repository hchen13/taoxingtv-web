# 暂停十分钟后续播验证 · 2026-10-05

## 方法与范围

Claire 本机现有部署，Codex 内置 Chromium 浏览器，1 倍速静音播放。在片中通过实际播放/暂停按钮暂停，按真实墙钟等待至少十分钟，再通过同一按钮续播。没有改动系统时间，也没有缩短超时来代替等待。

临时浏览器监测记录按钮事件、requestVideoFrameCallback 新运动帧、加载遮罩、每秒播放进度与连续缓冲；服务端每两秒记录会话、缓存和取流状态。恢复首帧必须是暂停位置之后的新帧，不能把停留在屏幕上的旧画面算作恢复。续播观察超过暂停时约三分钟的浏览器缓冲，并检查后台重新补入数据。

这里验证的是页面保持打开、电脑没有休眠的点播暂停。页面 visibilityState 始终为 visible；未把此次结果扩展为电脑休眠、页面被浏览器回收或断网十分钟后的保证。没有变更 Clash、TUN、系统代理、DNS、路由或代理核心。

## 本轮修复：异常恢复保留用户暂停意图

代码检查和真实前端处理函数的隔离回归测试确认：用户已暂停时，网络异常恢复和解码转码回退原先没有把暂停状态传到新播放器，完成预缓冲后可能自动播放。反过来，解码器自己因错误暂停，也不能被保存成用户要求暂停。

前端现在分别保留用户暂停意图和底层媒体元素的暂停状态。点击暂停、系统媒体键暂停会被保留；恢复、转码回退和保存页面进度沿用这一意图；用户主动继续播放或换集、跳转优先于旧状态。没有为了缩短首帧而降低起播缓存门槛。

第一轮《黄石》使用未刷新页面作为正常暂停基线；第一轮不中断计时，修复在此期间完成。第二轮 Silo 使用新加载的修复后页面。异常恢复边界由实际 UI 处理函数的隔离测试验证，这两轮正常十分钟测试没有人为制造取流故障。

第二轮进行中另补充了媒体结束事件的保护，避免把自动结束时的暂停误记为用户暂停；该边界通过新增回归测试验证，没有为了加载这一保护而打断十分钟暂停计时。

新增 11 项前端状态回归测试，覆盖主动暂停、系统媒体键、网络恢复、转码回退、解码器自动暂停、恢复退避期间继续播放、主动换集/跳转、媒体提前结束和状态持久化。项目全部 22 项测试通过。
